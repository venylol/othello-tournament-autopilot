# 当前选手对局调查方法

## 一、分析范围

调查开始时必须明确：

- 被调查账号；
- Othello Quest 当前可见对局范围；
- 预先指定的被报告对局；
- 其余对局作为个人对照组；
- 已有 EG 分析的参数及结果目录。

被报告局不能因为分析结果而事后更换。程序不会把统计量转换成“作弊概率”。

## 二、原始事件与实际落子

OQ `position.moves` 中包含三类事件：

- 坐标着手；
- 显式 pass；
- 没有坐标的终局或认输事件。

用时保留原始 `t` 毫秒值。只有坐标着手拥有 EG 子损。pass 和终局事件保留
用时，但不计算子损。

## 三、子损统计

子损直接读取已有 EG `lossClipped`，不在工具箱中重新调用引擎。

### 3.1 两种平均口径

- 局等权：先计算每局平均子损，再让每局权重相同。
- 着手等权：把所有实际着手合并，每一手权重相同。

两者同时输出，用于识别结果是否被个别长对局的着手数量影响。

### 3.2 整局聚类 bootstrap

重采样单位是整局，不是单手。每次分别从被报告局和对照局中有放回抽取相同
数量的整局，再计算差值。95%区间取重采样差值的2.5%和97.5%分位。

### 3.3 精确组合位置

如果被报告组有两局，就枚举同一比较范围内的全部两局组合，计算被报告组合
在这些组合中的升序位置。这是样本内的精确经验位置，不是作弊概率。

### 3.4 单步两部分模型

模型拆分两个问题：

1. 某手是否为零子损；
2. 已经发生正子损时，损失有多大。

零子损部分使用 logistic 模型。正子损部分对正子损取自然对数后做线性回归，
再用 smearing correction 还原到原尺度。两部分均控制线性 ply、执棋颜色
和是否为比赛局。区间通过整局聚类 bootstrap 获得。

## 四、用时趋势

用时分析使用原始毫秒，不做对数变换。基线只使用与被报告局同色的个人对照
局，以算术平均为中心拟合带四个固定结点的三次回归样条，ridge alpha 为0.1。

每手残差为：

```text
实际用时 - 同 ply 基线预测用时
```

长考定义为实际用时高于相同 ply 对照分布第90百分位。被报告组合与全部同样
大小的对照局组合比较，并输出 plus-one 经验尾部位置。

## 五、特定选手 Human Frequency Book

### 5.1 建库单位

个人库不保存“只属于选手的坐标字符串”，而保存双方共同形成的完整棋盘节点：

```text
[board_string, occurrence_count, ply]
```

棋盘使用当前行动方视角：`X` 为当前方，`O` 为对手，`-` 为空位；然后在8种
旋转、镜像中取字典序最小表示。

黑棋和白棋分别建库。被报告对局全部排除。

### 5.2 评价某次选择

轮到被调查选手时：

- `parent_book_count`：落子前完整局面的历史次数；
- `book_count`：实际落子后子局面的历史次数；
- `book_hit`：子局面是否有历史先例；
- `parent_child_ratio`：子局面次数除以父局面次数。

结果分为：

- `historical_choice`：父局面和实际子局面都在个人库中；
- `new_player_choice`：父局面存在，但选手走出的子局面未见；
- `unseen_parent`：对手应对或此前分支已使当前局面离开个人库。

对手着手不计入选手命中数，但必须参与完整棋盘重建。

### 5.3 对照局留一法

评价每盘对照局时，该局自身从个人库排除。否则对照局一定能找到自己，命中率
会被系统性抬高。

每局主要输出：

- 历史局面覆盖率；
- 历史选择命中率；
- 从开局开始的连续历史选择数；
- 第一次离库发生在哪次个人选择；
- 第一次离库由个人新选择还是历史未见父局面造成。

## 六、标准定式名称与筛选

标准定式由独立的 `standard_openings.json` 维护，每条记录包含稳定 `id`、显示
名称、着手序列和可选别名。目录只记录人工确认的定式，不根据统计结果自动发明
名称。

匹配使用双方完整实际落子序列。定式序列和对局的同长度前缀分别在8种旋转、
镜像下取规范表示；两者相同即为包含该定式。若一局同时匹配多个嵌套定式，最长
序列作为该局最具体的 `opening`，全部匹配保留在 `openingMatches`。

该功能与个人 Human Frequency Book 分开：标准定式回答公开名称和序列匹配，
个人库回答目标选手是否走过自己的历史选择。

## 七、Agent 手工脱谱位置

脱谱位置不能由脚本自动判定。脚本只生成审查所需的事实字段，Agent 必须逐局
人工作出 `offbook` 或 `no_offbook` 判断，然后通过单独的登记阶段保存结果。

人工判断必须把逐 ply 原始思考时间及其局内连续性放在首位。Agent 应寻找目标
选手从连续、快速、像是熟悉路线的落子，转为需要明显现场思考的首次可信转折；
同时查看该手前后的连续用时，排除单个网络抖动、强制着手、终局收官或偶发长考。
不得设置固定秒数阈值，也不得因为某一手恰好较长就自动标记。

目标选手审查包包含每个实际落子 ply 的 OQ 原始毫秒用时，以及同色留一法
Frequency Book 中的父节点、落子后节点、出现次数和比例。可预先指定一组对局
从所有个人库中排除。排行榜参照选手没有 Frequency Book 时，审查包只提供逐
ply 原始用时，仍由 Agent 人工决定并记录。

Human Frequency Book 只作为弱历史参考。样本内未见父节点、未见子节点或低
父子比例，都不能单独证明选手已经脱离熟悉路线，更不能直接成为锚点；个人库
样本较小时尤其如此。反过来，历史命中也不能推翻清晰的思考时间转折。EG 子损
和选择前后连续性用于解释背景，但锚点仍应主要由原始思考时间的人工判断确定。
若完整审查后仍无法可靠确定首次转折，应登记 `no_offbook` 并在备注中说明证据
不足，不得把“首次样本未见节点”机械替代为脱谱点。

每局 `agentNote` 必须非空，并简洁记录锚点前后的原始用时连续性；如引用
Frequency Book，必须明确它只是弱参考。登记脚本只校验备注存在，不自动判断
备注内容或锚点是否正确，最终判断仍由 Agent 负责。

脱谱点必须是目标选手本人的实际着手：目标执白时只能标白方着手，目标执黑时
只能标黑方着手。程序依据实际回放所得 `playerColor` 校验，不仅依赖 ply 奇偶。
每局最多记录一个首次脱谱点。

脱谱后指标从该标记手开始并包含该手。单独输出：

- 脱谱后局等权和着手等权子损；
- 脱谱后原始毫秒用时的局等权和着手等权 mean；
- 整局指标，用作同一输出中的参照；
- 目标选手与人工标记过的排行榜高分选手参照组之间的差值。

`no_offbook` 对局进入整局统计，但不进入脱谱后单元。所有边界均来自经过校验
的 Agent 人工记录，统计阶段不会推断或改写脱谱位置。

## 八、外部参照组

外部排行榜参照按实际采样对局分组。每组输出：

- 局数、着手数；
- 局等权和着手等权平均子损；
- 零子损率、正子损平均值、子损大于等于4的比例；
- Ply 1-20、21-40、41以后分段统计。

如果同一选手贡献多局，结果是“对局组合的经验位置”，不能当作同等数量的独立
选手样本。

## 九、报告呈现

报告应先给出描述性结论，再解释计算口径。开局部分不再使用“只抽取选手坐标后
比较序列”的旧方法。PDF 由 Markdown 通过 GitHub Issue 风格渲染脚本生成，
Markdown 保持为报告的可编辑源文件。
